Phần 1: Phân tích sự cố

1. 4 lỗi sai của thực tập sinh

  • Sai về DNS: Nghĩ không cần DNS mà gửi thẳng URL tới Web Server. (Thực tế bắt buộc phải qua DNS để đổi tên miền thành IP).
    • Sai về TCP/TLS: Nghĩ không cần bắt tay mạng. (Thực tế bắt buộc phải có TCP 3-way handshake và TLS handshake để mở kết nối an toàn).
    • Sai về Mã lỗi HTTP: Lỗi sập Database nhưng lại trả về 404 Not Found và bảo mất hồ sơ. (Thực tế lỗi server phải trả về 500 Internal Server Error).
    • Sai về Tab Elements (DevTools): Tưởng gõ sửa chữ trên màn hình là đổi được dữ liệu gốc trên máy chủ. (Thực tế chỉ đổi tạm trên RAM máy cá nhân).

2. Phân tích mã 500 vs 404 và Hậu quả tâm lý

  • Vì sao là 500? 404 là sai đường dẫn/mất trang; còn 500 là lỗi nội bộ server/database bị sập. Sập database phải báo 500.
    • Hậu quả tâm lý: Báo nhầm 404 (“đã xóa vĩnh viễn hồ sơ”) sẽ làm bệnh nhân hoảng loạn, lo sợ mất dữ liệu khám bệnh, mất niềm tin nghiêm trọng vào hệ thống y tế.

Phần 2: Sửa lỗi & Giải pháp

3. Biên bản kỹ thuật chuẩn xác theo Vòng đời HTTP

  1. DNS Lookup: Phân giải tên miền carepulse.vn thành địa chỉ IP máy chủ.
    2. TCP/TLS Handshake: Bắt tay 3 bước và thiết lập mã hóa bảo mật HTTPS.
    3. HTTP Request & Response: Gửi yêu cầu lấy dữ liệu; Server phản hồi mã 500 Internal Server Error do lỗi Database.
    4. Rendering Pipeline: Trình duyệt dựng giao diện thông báo lỗi hệ thống tạm thời để người dùng nắm bắt.

4. Vì sao sửa trên DevTools không lưu vào máy chủ?

  • Client-side vs Server-side: Dữ liệu sửa trên DevTools chỉ nằm tạm trên bộ nhớ RAM của máy tính cá nhân, còn dữ liệu thật nằm trên Database của máy chủ.
    • Không gửi request: Thao tác gõ phím đó không tạo ra gói tin mạng nào gửi về server.
    • Mất khi F5: Chỉ cần bấm tải lại trang (F5), trình duyệt gọi lại server và dữ liệu gốc sẽ ghi đè ngay lập tức.
